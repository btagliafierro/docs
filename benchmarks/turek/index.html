    Turek-Hron FSI Benchmark¶

    This example reproduces the well-known Turek-Hron fluid-structure interaction (FSI) benchmark, using a flexible structures module. The flap, clamped on to the rigid cylider, deforms and oscillates under the hydrodynamic loading of the incoming flow. This case is built parametrically, and inlet/outlet open-boundary formulation is used with a time-varying parabolic velocity profile. Modified Dynamic Boundary Conditions (mDBC) are used for the whole set of solid boundaries.

    What's Covered in This Tutorial

    This case demonstrates the following DualSPHysics capabilities:

    • Parametric case definition using reusable variables (newvarcte) for geometry and physical quantities
    • Open boundary conditions (inlet/outlet) with a time-varying, parabolic velocity profile
    • Modified Dynamic Boundary Conditions (mDBC) with precomputed boundary normals
    • Free-draw geometry generation for a smooth circular boundary
    • Fluid-structure interaction via the flexstrucs (flexible structures) module

    Case Configuration¶

    Physical Setup¶

    The simulation represents a 2-D channel flow with:

    • Channel: 2.50 m long × 0.41 m high
    • Cylinder: 0.10 m diameter, centred at (0.20, 0.20) m
    • Elastic flap: clamped to the cylinder, extending downstream to \(x\) = 0.60 m, 0.02 m thick, centred on the channel mid-height
    • Particle spacing: dp = 0.0025 m

    For this case, we use:

    • Fluid mkfluid=0 for the bulk of the channel, mkfluid=1 for the inlet zone and mkfluid=2 for the outlet zone
    • Boundary mkbound=0 for the channel walls, mkbound=1 for the cylinder and mkbound=2 for the elastic flap

    Parametric Geometry Definition¶

    <predefinition>
    <newvarcte cyl_freedraw="true" mdbc="true" />
    <newvarcte dom_padding="0.1" inout_layers="8" />
    <newvarcte fluid_min_x="0.0" fluid_max_x="2.5" fluid_min_z="0.0" fluid_max_z="0.41" />
    <newvarcte cyl_cen_x="0.2" cyl_cen_z="0.2" cyl_radius="0.05" />
    <newvarcte struc_min_x="#cyl_cen_x" struc_max_x="0.6" struc_min_z="0.19" struc_max_z="0.21" />
</predefinition>

    Reusable variables: newvarcte defines named constants (#cyl_radius, #fluid_max_x, etc.) that are referenced throughout the rest of the geometry and execution blocks. This keeps the channel size, cylinder position, flap dimensions and switches such as mdbc and cyl_freedraw centralised in one place, so the whole case can be resized or reconfigured by editing only these few lines.

    Switches: mdbc="true" and cyl_freedraw="true" are boolean-style flags used later in the file (via #eval(...) and setfrdrawmode) to toggle the boundary method and the cylinder drawing mode without duplicating geometry commands.

    Domain Setup¶

    <definition dp="0.0025" units_comment="metres (m)">
    <pointref x="0" y="0" z="0" />
    <pointmin x="#fluid_min_x-(inout_layers+4)*Dp-dom_padding" y="0.0" z="#fluid_min_z-dom_padding" />
    <pointmax x="#fluid_max_x+(inout_layers+4)*Dp+dom_padding" y="0.0" z="#fluid_max_z+dom_padding" />
</definition>

    Particle spacing (dp): The inter-particle distance is 0.0025 m, which fine enough to resolve the boundary layer around the cylinder and the bending of the thin flap. However, a particle size of about 1mm is required to compare against literature results.

    Domain sized from variables: the placement domain is computed directly from the fluid extents, the number of inlet/outlet particle layers (inout_layers) and a general dom_padding, guaranteeing enough space for the open-boundary buffer zones on both sides of the channel.

    Geometry for mDBC Normals¶

    <list name="GeometryForNormals">
    <setactive drawpoints="0" drawshapes="1"/>
    <setshapemode>actual | bound</setshapemode>
    <setnormalinvert invert="true" />
    <setmkbound mk="0" />
    <drawbox>
        <boxfill>top | bottom</boxfill>
        <point x="#tank_min_x" y="#-dom_padding" z="#tank_min_z+Dp/2" />
        <size x="#tank_max_x-tank_min_x" y="#2*dom_padding" z="#tank_max_z-tank_min_z-Dp" />
    </drawbox>
    <setnormalinvert invert="false" />
    <setmkbound mk="1" />
    <drawcylinder radius="#cyl_radius+Dp/2">
        <point x="#cyl_cen_x" y="#-dom_padding" z="#cyl_cen_z" />
        <point x="#cyl_cen_x" y="#dom_padding" z="#cyl_cen_z" />
    </drawcylinder>
    <setmkbound mk="2" />
    <drawbox>
        <boxfill>top | bottom | right</boxfill>
        <point x="#struc_min_x" y="#-dom_padding" z="#struc_min_z-Dp/2" />
        <size x="#struc_max_x-struc_min_x+Dp/2" y="#2*dom_padding" z="#struc_max_z-struc_min_z+Dp" />
    </drawbox>
    <shapeout file="hdp" />
    <resetdraw />
</list>

    Purpose: this reusable command list does not generate the final simulation particles; it draws a slightly offset version of the walls, cylinder and flap (note the +Dp/2 offsets) purely to produce the hdp shape file used afterwards to compute accurate boundary normals for mDBC.

    Normal orientation: setnormalinvert flips the normal direction for the channel walls (which face inward) relative to the cylinder and flap (which face outward), ensuring all boundary normals point consistently into the fluid domain.

    Isolated execution: because this geometry is only needed for the normals calculation, it is defined as a named list and executed with runlist from the main command sequence, then reset with resetdraw so it does not persist as part of the actual case geometry.

    Main Geometry¶

    <newvarcte tank_min_x="#fluid_min_x-(inout_layers+4)*Dp" tank_min_z="#fluid_min_z" />
<newvarcte tank_max_x="#fluid_max_x+(inout_layers+4)*Dp" tank_max_z="#fluid_max_z" />
<runlist name="GeometryForNormals" />
<setdrawmode mode="full" />
<setmkfluid mk="0" />
<drawbox>
    <boxfill>solid</boxfill>
    <point x="#fluid_min_x" y="#-dom_padding" z="#fluid_min_z" />
    <size x="#fluid_max_x-fluid_min_x" y="#2*dom_padding" z="#fluid_max_z-fluid_min_z" />
</drawbox>
<setmkfluid mk="1" />
<drawbox>
    <boxfill>left</boxfill>
    <point x="#fluid_min_x" y="#-dom_padding" z="#fluid_min_z" />
    <size x="#fluid_max_x-fluid_min_x" y="#2*dom_padding" z="#fluid_max_z-fluid_min_z" />
</drawbox>
<setmkfluid mk="2" />
<drawbox>
    <boxfill>right</boxfill>
    <point x="#fluid_min_x" y="#-dom_padding" z="#fluid_min_z" />
    <size x="#fluid_max_x-fluid_min_x" y="#2*dom_padding" z="#fluid_max_z-fluid_min_z" />
</drawbox>
<setmkbound mk="0" />
<drawbox>
    <boxfill>top | bottom</boxfill>
    <point x="#tank_min_x" y="#-dom_padding" z="#tank_min_z" />
    <size x="#tank_max_x-tank_min_x" y="#2*dom_padding" z="#tank_max_z-tank_min_z" />
    <layers vdp="0,1,2,3,4" />
</drawbox>
<setfrdrawmode auto="#cyl_freedraw" />
<setmkbound mk="1" />
<drawcylinder radius="#cyl_radius">
    <point x="#cyl_cen_x" y="#-dom_padding" z="#cyl_cen_z" />
    <point x="#cyl_cen_x" y="#dom_padding" z="#cyl_cen_z" />
</drawcylinder>
<setfrdrawmode auto="false" />
<setmkbound mk="2" />
<drawbox>
    <boxfill>solid</boxfill>
    <point x="#struc_min_x" y="#-dom_padding" z="#struc_min_z" />
    <size x="#struc_max_x-struc_min_x" y="#2*dom_padding" z="#struc_max_z-struc_min_z" />
</drawbox>

    Bulk fluid: setmkfluid mk="0" fills the whole channel cross-section solidly with fluid particles.

    Inlet and outlet marking: two thin slices at the left and right edges of the fluid domain are re-marked as mkfluid=1 (inlet) and mkfluid=2 (outlet). These particles are not geometrically distinct from the rest of the fluid; the separate marker is what lets the inout configuration (below) recognise and treat them as open-boundary zones.

    Layered walls for mDBC: the channel walls (mkbound=0) are drawn with layers vdp="0,1,2,3,4", generating five stacked layers of boundary particles at increasing depth, which is the layer arrangement mDBC needs to correctly extrapolate pressure and velocity from the fluid to the wall.

    Free-draw cylinder: setfrdrawmode auto="#cyl_freedraw" switches on automatic free-draw placement for the cylinder, giving a smoother particle distribution around the curved boundary than a fixed-lattice projection would; it is switched back off immediately afterwards so it does not affect the flap.

    Elastic flap boundary: the flap is drawn as a solid box (mkbound=2) directly attached to the cylinder at \(x\) = 0.20 m, forming the structural body that will later be coupled to the flexible-structure solver.

    Boundary Normals¶

    <normals active="true">
    <norgeometry comment="Define initial configuration of normals before applying other configurations">
        <geometryfile file="[CaseName]_hdp_Actual.vtk" comment="File with boundary geometry (VTK format)" />
        <distanceh v="2" comment="Maximum orthogonal distance (H*value) to compute normals data" />
        <maxsizeh v="0" comment="Maximum allowed normal size (H*value) (disabled=0)" />
        <svshapes v="true" comment="Saves VTK with geometry in triangles and quads with its normals for debug" />
    </norgeometry>
</normals>

    This block feeds the hdp geometry file produced earlier into GenCase's normals calculator, computing a boundary normal for every mDBC particle up to a distance of 2\(H\), which is what allows mDBC to correctly extrapolate fluid quantities onto the walls, cylinder and flap.

    Flap Boundary Motion¶

    <motion>
    <objreal ref="2">
        <begin mov="1" start="0" />
        <mvnull id="1" />
    </objreal>
</motion>

    The flap (mkbound=2) is assigned a null motion (mvnull). This is not an oversight: the flap is not meant to move as a rigid body under a prescribed law, but to deform under the fluid loading according to the elastic material model defined in flexstrucs below. The mvnull entry simply confirms that no external kinematic motion is imposed, leaving the structural solver in full control of its displacement.

    Open Boundaries (Inlet/Outlet)¶

    <inout>
    <memoryresize size0="2" size="4" comment="Initial memory resize and following resizes" />
    <determlimit value="1e-3" comment="Use 1e-3 for first_order or 1e+3 for zeroth_order" />
    <extrapolatemode value="3" comment="Calculation mode for rhop/velocity extrapolation from ghost nodes: 3:double" />
    ...
</inout>

    Extrapolation settings: determlimit="1e-3" selects first-order extrapolation from ghost nodes, and extrapolatemode="3" uses the more accurate double-precision extrapolation for reconstructing pressure and velocity at the open boundaries.

    Inlet Zone (mkfluid=1)¶

    <inoutzone>
    <refilling value="0" comment="Simple full refilling" />
    <inputtreatment value="2" comment="Remove fluid entering the zone (recommended for inlet)" />
    <layers value="#inout_layers" comment="Number of inlet/outlet particle layers" />
    <zone2d>
        <particles mkfluid="1" direction="right" />
    </zone2d>
    <imposevelocity mode="1" comment="Variable value">
        <velocitytimes3 comment="Parabolic inlet velocity in time">
            <timevalue time="0.0" v2="0.0" z="0.0" z2="0.205" z3="0.41" />
            <timevalue time="1.0" v2="0.75" z="0.0" z2="0.205" z3="0.41" />
            <timevalue time="2.0" v2="1.5" z="0.0" z2="0.205" z3="0.41" />
        </velocitytimes3>
    </imposevelocity>
    <imposerhop mode="2" comment="Extrapolated from ghost nodes" />
    <imposezsurf mode="0">
        <zsurf value="#fluid_max_z" />
        <remove value="false" />
    </imposezsurf>
</inoutzone>

    Direction and treatment: the inlet zone corresponds to the mkfluid=1 particles, with flow entering in the right (+\(x\)) direction; inputtreatment="2" removes any fluid that would otherwise cross back into the inlet buffer, which is the recommended setting for a well-posed inlet.

    Time-varying parabolic profile: velocitytimes3 imposes a parabolic velocity profile across the channel height, defined by three reference heights (\(z\)=0, \(z_2\)=0.205, \(z_3\)=0.41 — bottom, mid-height and top) at each time-value entry. The mid-height velocity \(v_2\) is ramped smoothly from 0 to 1.5 m/s over the first 2 s of the simulation, giving a gentle, numerically well-behaved start-up rather than an impulsive inflow — a standard feature of the Turek-Hron benchmark protocol.

    Density and free surface: rhop is extrapolated from the interior flow, and the characteristic inlet water surface is fixed at \(z\) = 0.41 m (the full channel height), since the channel runs completely full.

    Outlet Zone (mkfluid=2)¶

    <inoutzone>
    <refilling value="2" comment="Advanced refilling for reverse flows" />
    <inputtreatment value="1" comment="Convert fluid (necessary for outlet)" />
    <layers value="#inout_layers" />
    <zone2d>
        <particles mkfluid="2" direction="left" />
    </zone2d>
    <imposevelocity mode="2" comment="Extrapolated value" />
    <imposerhop mode="0" comment="Imposed fixed value" />
    <imposezsurf mode="0">
        <zsurf value="#fluid_max_z" />
        <remove value="false" />
    </imposezsurf>
</inoutzone>

    Outlet behaviour: the outlet zone (mkfluid=2, direction left, i.e. facing back into the domain) extrapolates its velocity from the interior flow rather than imposing a fixed value, and uses the more expensive but more robust "advanced" refilling mode, which is recommended whenever reverse flow through the outlet (caused by the wake behind the cylinder and flap) is expected.

    Flexible Structure (FSI Coupling)¶

    <flexstrucs>
    <flexstrucbody mkbound="2" mkclamp="1">
        <density value="10000.0" comment="Mass density" units_comment="kg/m^3" />
        <youngmod value="1.4e6" comment="Young Modulus" units_comment="Pa" />
        <poissratio value="0.4" comment="Poisson ratio" />
        <constitmodel value="1" comment="Constitutive model 1:Plane Strain (2D)" />
        <hgfactor value="0.1" comment="Hourglass correction factor" />
    </flexstrucbody>
</flexstrucs>

    Coupling definition: flexstrucbody designates the boundary particles with mkbound=2 (the flap) as a deformable elastic body, clamped at mkclamp="1" — the cylinder — so that the flap is rigidly attached to the cylinder at its root and free to bend along its length.

    Material properties: the flap is given a density of 10,000 kg/m³, a Young's modulus of 1.4 × 10⁶ Pa and a Poisson ratio of 0.4, matching the classical Turek-Hron benchmark parameters that produce a large, low-frequency bending oscillation under the incoming flow.

    Constitutive model and stabilisation: a plane-strain formulation is used, appropriate for this 2-D case, and a small hourglass correction factor (0.1) is applied to suppress spurious zero-energy deformation modes in the structural discretisation.

    Numerical Parameters¶

    Boundary Method¶

    <parameter key="Boundary" value="#eval(mdbc,2,1)" comment="Boundary method 1:DBC, 2:mDBC" />
<parameter key="SlipMode" value="2" comment="Slip mode for mDBC 2:No-slip" />
<parameter key="NoPenetration" value="0" comment="Prevent particle penetration in mDBC: Off" />

    Since the mdbc variable is set to true, #eval(mdbc,2,1) evaluates to 2, selecting mDBC with a no-slip condition at all solid boundaries (walls, cylinder and flap).

    Kernel and Viscosity¶

    <parameter key="StepAlgorithm" value="2" comment="Symplectic" />
<parameter key="Kernel" value="2" comment="Wendland" />
<parameter key="ViscoTreatment" value="2" comment="Laminar+SPS" />
<parameter key="Visco" value="0.001" comment="Viscosity value" />
<parameter key="ViscoBoundFactor" value="1" comment="Multiply viscosity value with boundary" />

    A Laminar+SPS viscosity formulation is used with a low viscosity value of 0.001, appropriate for the moderate-Reynolds-number laminar flow of the benchmark, with full viscous coupling at the boundary (ViscoBoundFactor="1").

    Density Diffusion and Shifting¶

    <parameter key="DensityDT" value="1" comment="Molteni" />
<parameter key="DensityDTvalue" value="0.1" comment="DDT value" />
<parameter key="Shifting" value="3" comment="Full" />
<parameter key="ShiftCoef" value="-20" comment="Coefficient for standard shifting computation" />
<parameter key="ShiftTFS" value="0.0" comment="Free-surface detection threshold" />

    The Molteni density diffusion term is used with δ = 0.1, and full particle shifting is enabled with a strong coefficient (-20) to maintain a regular particle distribution around the cylinder and along the oscillating flap, where large local deformations would otherwise degrade particle quality.

    Time Step and Stopping Criteria¶

    <parameter key="CoefDtMin" value="0.001" comment="Coefficient to calculate minimum time step" />
<parameter key="DtAllParticles" value="1" comment="Velocity of all particles used to calculate DT" />
<parameter key="TimeMax" value="15.0" comment="Time of simulation" units_comment="seconds" />
<parameter key="TimeOut" value="0.05" comment="Time out data" units_comment="seconds" />
<parameter key="MinFluidStop" value="0.5" comment="Minimum proportion of initial fluid particles to continue" />

    All-particle time-step control: DtAllParticles="1" includes boundary and flexible-structure particles (not just fluid) in the time-step calculation, which is important here since the flap's own motion can otherwise become the limiting factor for stability.

    Simulation length: the case runs for 15 s, long enough for the inflow ramp-up (2 s) followed by several periods of the flap's self-sustained oscillation.

    Mass conservation safeguard: MinFluidStop="0.5" automatically stops the simulation if the number of fluid particles falls below 50% of the initial count, guarding against runaway mass loss through the open boundaries.

    Simulation Domain¶

    <simulationdomain comment="Defines domain of simulation">
    <posmin x="default - 5%" y="default" z="default - 5%" />
    <posmax x="default + 5%" y="default" z="default + 5%" />
</simulationdomain>

    The computational domain is extended by 5% beyond the generated particle bounding box in both \(x\) and \(z\), giving the open boundaries and the deforming flap a small additional margin.

    Running the Simulation¶

    Execute the case using the provided batch/shell script:

    Windows¶

    wCaseTurekFSI_win64_GPU.bat
    REM Generate case geometry
gencase.exe CaseTurekFSI_Def CaseTurekFSI_out/CaseTurekFSI -save:all

REM Run simulation on GPU
dualsphysicsgpu.exe -gpu CaseTurekFSI_out/CaseTurekFSI CaseTurekFSI_out/CaseTurekFSI/data

REM Convert to VTK format
partvtk.exe -dirdata CaseTurekFSI_out/CaseTurekFSI/data -savevtk post/PartFluid -onlytype:-all,+fluid

    Linux¶

    xCaseTurekFSI_linux64_GPU.sh
    # Generate case geometry
./gencase CaseTurekFSI_Def CaseTurekFSI_out/CaseTurekFSI -save:all

# Run simulation on GPU
./dualsphysicsgpu -gpu CaseTurekFSI_out/CaseTurekFSI CaseTurekFSI_out/CaseTurekFSI/data

# Convert to VTK format
./partvtk -dirdata CaseTurekFSI_out/CaseTurekFSI/data -savevtk post/PartFluid -onlytype:-all,+fluid

    Parametric case

    Because this case is built almost entirely from #variables, most changes — channel size, cylinder position, flap length, material properties — can be made by editing the predefinition block and the flexstrucbody material entries, without touching the drawing commands themselves.

    Results and Validation¶

    As the parabolic inflow ramps up, vortices begin to shed from the cylinder and impinge on the elastic flap, which starts to oscillate. Once the inflow reaches its steady value, the flap settles into a large-amplitude, self-sustained bending oscillation driven by the periodic vortex shedding, characteristic of the Turek-Hron benchmark. The typical quantities of interest for validation are the time history of the flap tip displacement in the streamwise and transverse directions, and the drag and lift forces on the cylinder-flap assembly, both of which can be compared against the reference values reported in the original Turek-Hron benchmark study and against other FSI solvers that have reproduced it.

    References¶
