    How-To: Compute the Motion of a Floating Body¶

    Use FloatingInfo to extract floating-body time series from recorded DualSPHysics simulation information. It post-processes the motion already calculated by the simulation; it does not change that motion or perform another fluid–structure interaction calculation.

    1. Locate the floating-body data¶

    Start with existing results from examples/benchmarks/06_FloatingBox/. FloatingInfo reads PartFloatInfo.ibi4, which contains floating-body information, rather than interpolating particle velocities at measurement points. Keep the simulation's associated data together in FloatingBox_out/data/.

    The normal v6 input option is -dirdata <dir>. For variable-resolution simulations it takes the main output directory instead. The separate -dirdatax <dir> reads the extra-frequency floating data, PartFloatInfo2.ibi4, when that output exists. An ordinary particle VTK series alone is not a substitute for these floating records.

    2. Identify the floating marker¶

    Use the generated case information and simulation log to identify the MK of the floating body. -onlymk selects floating bodies by that marker, not by a particle ID or a body's ordinal number.

    The FloatingBox XML defines the body with local boundary identifier mkbound="50". The generated global MK also includes the boundary-marker offset; do not assume that mkbound and MK are interchangeable. Check the mapping for the actual output before selecting a different body.

    The benchmark command uses -onlymk:10-120: the hyphen defines an inclusive range of MK values, 10 through 120. Floating bodies whose markers fall in that range are selected; this does not create 111 bodies or select fixed/moving walls as floatings. The range is specific to this example. Choose markers belonging to the floating bodies of interest in another simulation.

    3. Extract the motion¶

    Work in a Windows Command Prompt in examples/benchmarks/06_FloatingBox/. The following post-processing fragment uses the variables from wFloatingBox_win64_GPU.bat, after its simulation results exist:

    set name=FloatingBox
set dirout=%name%_out
set diroutdata=%dirout%\data
set dirbin=../../../bin/windows
set floatinginfo="%dirbin%/FloatingInfo_win64.exe"
set dirout2=%dirout%\post

    Define these variables in the same command session or BAT before using:

    %floatinginfo% -dirdata %diroutdata% -savemotion -onlymk:10-120 -savedata %dirout2%/

    The fragment does not run GenCase or the solver. %floatinginfo% includes the quoted executable path; %diroutdata% points to the simulation data and %dirout2% to the CSV output directory. Adapt paths for another installation, quoting directory arguments if they contain spaces.

    Option Meaning
    -dirdata %diroutdata% Read the saved floating-body data.
    -savemotion Include motion data in the floating CSV output. The explicit control is -savemotion:0/1, enabled by default.
    -onlymk:10-120 Select floating bodies with MK in the indicated range.
    -savedata %dirout2%/ Generate floating-data CSV files under FloatingBox_out/post/.

    4. Read the time series¶

    The floating CSV naming pattern is _mk<marker>.csv; for example, _mk60.csv identifies MK 60. Open the files for the selected floatings in FloatingBox_out/post/. The accompanying postFloater.m illustrates reading the _mk60.csv series, including surge, heave and pitch. Use your actual output directory rather than copying another case's directory name from a plotting script.

    Read the CSV header before plotting: the available fields and motion columns depend on the saved data, dimensionality and output options. Typical header labels include part, time [s], fvel.x [m/s], fomega.x [rad/s] and center.x [m], with corresponding Cartesian components where present. The motion columns use labels such as surge [m], heave [m] and pitch [deg]. Do not assume a fixed column index or that every file contains every quantity below.

    Quantity Meaning and units
    center Position of the centre of mass, in m; distinguish position from displacement.
    surge, sway, heave Displacement of the centre of mass along X, Y and Z respectively, in m.
    roll, pitch, yaw Rotation about X, Y and Z respectively, in degrees.
    fvel Linear velocity of the floating body, in m/s.
    fomega Angular velocity, in rad/s.
    face, faceomega Linear and angular accelerations calculated from changes in the respective velocities, in m/s² and rad/s².

    For this 2-D x–z FloatingBox case, surge describes horizontal X displacement, heave vertical Z displacement, and pitch rotation about Y, normal to the simulation plane. Plot each quantity against time [s], retaining its units. Do not interpret center.x as surge or confuse pitch in degrees with angular velocity in rad/s. The pitch sign convention changed since v5.0.204; check conventions before comparing with older files or experimental axes.

    Other documented quantities, when present, include external linear/angular forces, fluid linear/angular forces, and acceleration before constraints. Use their own headers and units rather than treating these as additional displacement or rotation columns. For a separate particle-based force calculation, see Measure the force on an object.

    Limitations and checks¶

    • FloatingInfo requires the floating records for the selected simulation and bodies. If a series is missing, check the input directory, available PartFloatInfo.ibi4, generated MK mapping and selected range.
    • -savemotion:0 omits motion data; retain motion output when surge, heave or pitch are needed.
    • Extra-frequency data require PartFloatInfo2.ibi4 and the corresponding input option; they cannot be recovered from missing output by changing plotting settings.
    • Time-series resolution is limited by the recorded data. Inspect time values when selecting records with -first, -last or -files.
    • CSV separators are configurable with -csvsep; choose the matching separator when importing a file.
    • Particle or body geometry animation in ParaView provides spatial context; it is a different output from these body-level CSV time series.
